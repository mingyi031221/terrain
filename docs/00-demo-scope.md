# Terrain Demo Scope

## 1. 目标

做一个可以本地启动、在浏览器里直接演示的交互 demo，展示 `Terrain` 的核心体验：

1. 用户输入任意学习主题。
2. 系统实时生成一张学习地形图。
3. 用户点开节点查看微讲解。
4. 用户标记完成并看到地图状态变化。

第一版 demo 的目标不是做成完整产品，而是把“真实输入 -> 真实生成 -> 真实交互”这条主链路跑通。

## 2. Demo 范围

### 必做范围

- 单页 Web 应用，本地运行。
- 用户输入主题，触发实时地图生成。
- 地图包含 5 到 8 个山头节点与依赖连线。
- 每个节点展示标题、难度、预计时间、是否必经。
- 点击节点后，实时生成或加载 200 到 500 字微讲解。
- 支持节点完成标记。
- 支持本地刷新后恢复当前进度。
- 支持失败提示、重试和最低限度加载态。

### 推荐实现方式

- 前端负责输入、状态和可视化。
- 本地 server 负责：
  - 接收前端请求。
  - 调用 `LLM API`。
  - 校验返回结构。
  - 向前端返回干净数据。
- 历史记录和完成状态保存在浏览器本地。

### 可选增强

- 节点详情流式输出。
- 预置示例主题。
- 地图导出为图片。
- 微动画和过渡效果。

## 3. 非目标

以下内容不进入第一版 demo：

- 用户登录、账号体系、云同步。
- 生产级后端架构。
- 数据库。
- 分享链接、多人协作。
- 打包成桌面应用或移动应用。
- 微信小程序。
- 推荐系统和长期学习计划。

## 4. 为什么不是纯前端静态 demo

如果没有实时生成，这个项目演示的是界面，不是产品本身。你说得对，`Terrain` 的核心不是“有一张漂亮地图”，而是“用户输入一个主题后，系统能生成一张有路径感的地图”。这一步不成立，前端交互再顺也只是壳。

因此这版必须保留真实生成，但生成链路要压到最小：

- 不做复杂后端。
- 只做本地代理。
- 不做数据库。
- 不做用户体系。

## 5. 用户场景

### 演示场景

演示者打开网页后，可以展示：

1. 输入一个主题，例如“我想搞懂 Docker”。
2. 等待系统生成地图。
3. 点击一个山头查看解释。
4. 标记已完成。
5. 刷新页面，确认进度仍在。

### 建议演示主题

- Docker
- 回归分析
- 大模型 API

## 6. 成功标准

### 产品层

- 用户第一次看 demo 时，能在 10 秒内理解“山头”和“连线”分别表示什么。
- 输入一个真实主题后，用户能得到看起来合理的地图，而不是明显失真的占位结构。
- 用户能不经说明完成一次“点开节点并标记完成”。

### 工程层

- 本地一条命令启动前后端。
- 地图生成在常规网络下目标 15 秒内返回。
- 节点详情失败时页面不崩溃，且可重试。
- 刷新页面后，当前主题和完成状态可以恢复。
- 所有模型输出都经过结构校验。

## 7. Demo 发布标准

满足以下条件才算可演示：

1. 在本地浏览器环境中，能从输入主题到展开节点完整走通。
2. 地图和节点详情来自实时生成，不是纯静态切换。
3. 节点详情、完成标记、本地保存都可用。
4. 没有演示级别的空白状态、未处理异常或明显假数据残留。
