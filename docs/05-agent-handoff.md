# Agent Handoff Guide

## 1. 目标

这份文档用于让后续 agent 在“本地可运行的真实交互 demo”这个边界内继续推进。

## 2. 默认工作方式

- 每个 agent 一次只负责一个明确方向。
- 每次提交必须能说明：
  - 改了什么
  - 为什么现在改
  - 如何验证
- 如果发现文档和实现冲突，先以 `docs/` 为准，并补一个文档修正任务。

## 3. 建议分工

### Agent A: 工程骨架

负责：

- 前后端初始化
- 基础配置
- 本地运行脚本

### Agent B: 契约和 prompt

负责：

- 类型和 schema
- prompt 模板
- 响应结构校验

### Agent C: 界面交互

负责：

- 主题输入
- 地图渲染
- 详情面板
- 完成状态反馈

### Agent D: 收尾与测试

负责：

- 失败态补齐
- 本地持久化
- 基础测试
- README 和演示说明

## 4. 任务领取顺序

1. 先完成 `B-001` 和 `B-002`。
2. 再做 `B-003`，先把地图生成跑通。
3. `B-004` 接着做节点详情。
4. `B-005` 和 `B-006` 用来把 demo 收口。

## 5. 交接模板

每次交接建议写成下面格式：

```md
## 本次目标

## 已完成

## 未完成

## 改动文件

## 验证结果

## 下一步建议
```

## 6. 冲突处理

- 如果接口结构改了，前端和 server 都要同步检查。
- 如果 prompt 输出结构变了，schema 也必须一起改。
- 如果页面开始依赖假数据，必须明确标出来，不允许静默退化成静态 demo。

## 7. 交付标准

后续 agent 提交前，至少确认：

1. 本任务对应的 backlog 勾选项是否真的完成。
2. 主链路是否仍然是“输入 -> 生成 -> 展示 -> 完成”。
3. 没有引入登录、数据库、云同步等越界内容。

## 8. 当前建议第一步

直接从 `B-001 初始化工程骨架` 开始。当前最重要的是把本地前后端跑起来，并给地图生成留出最小真实链路。
